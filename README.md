R'Lyeh Pnakotic is the reusable C++20 implementation of the R'Lyeh public version format. It converts a project policy,
a commit calendar date, and the rightmost six hexadecimal digits of a commit hash into a deterministic four-component
version such as `232.-92.-378.172`. It can reverse that version into a date and six-digit hash suffix suitable for
locating the authoritative commit.

The format is deterministic reversible obfuscation for public version branding. It is not encryption and provides no
cryptographic security. Pnakotic never invokes Git; callers obtain their own SCM data and pass it to the library.

## Project policies and epochs

The shared codec has no calendar context of its own. Each supported project therefore has a `ProjectPolicy` containing
its identity, display name, and epoch: the calendar date from which the encoded signed day delta is measured. Independent
epochs let multiple projects use the same bit-level format without forcing their histories onto a common timeline.

Pnakotic owns the authoritative policy definitions in `RLyehPnakotic/ProjectPolicy.h`. Consumers select a policy but
should not duplicate its epoch, because differing epoch values would encode and decode the same version inconsistently.
A policy may mark its epoch as provisional while a project establishes its permanent calendar origin; the concrete date
and transition rules belong to that policy rather than to the generic format.

Project release conventions outside the four-component `X.Y.Z.W` format are not generated by Pnakotic. Additional
projects can be added through policy data without changing the generic codec.

## Standalone build and test

```sh
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

The library is header-only so its complete implementation remains available for compile-time encoding and decoding.
The test executable is built with only the C++ standard library.

## Using the library

Include the public umbrella header:

```cpp
#include <RLyehPnakotic/Pnakotic.h>
```

Callers obtain their own SCM metadata and pass it with an authoritative project policy:

```cpp
using namespace RLyeh::Pnakotic;

SCMVersionResult EncodeForProject(const ProjectPolicy& project,
                                  std::string_view commit_date,
                                  std::string_view full_hash)
{
  return EncodeSCMVersion(project, commit_date, full_hash);
}

SCMLocatorResult DecodeForProject(const ProjectPolicy& project,
                                  std::string_view public_version)
{
  return DecodeSCMVersion(project, public_version);
}
```

Dates use strict `YYYY-MM-DD` form. A hash must contain at least six hexadecimal characters; the encoder validates the
entire supplied value and stores its rightmost six characters as the 24-bit locator. Encoding and decoding return a
status plus `valid()` rather than throwing exceptions. The APIs and their fixed-capacity result strings support constant
evaluation, allowing consumers to derive public versions during compilation.

The installed public API consists of four headers. `Pnakotic.h` is the umbrella include, while `Codec.h`,
`ProjectPolicy.h`, and `Version.h` expose the lower-level codec, project-policy, and SCM-version interfaces for consumers
that need them directly. The authoritative bit-level specification is in
[docs/version-format.md](docs/version-format.md).

## Vendored source consumption

When Pnakotic is cloned, vendored, or otherwise present in the consumer's source tree, add it directly and link its
namespaced target:

```cmake
add_subdirectory(path/to/RLyehPnakotic)
target_link_libraries(your-target PRIVATE RLyeh::Pnakotic)
```

## CMake installation

Install Pnakotic into a dependency prefix and point consumers at that prefix:

```sh
cmake --preset release
cmake --build --preset release
cmake --install build/release --prefix /path/to/deps/RLyehPnakotic --component RLyehPnakotic
```

An installed consumer can then use the same namespaced target:

```cmake
find_package(RLyehPnakotic CONFIG REQUIRED)
target_link_libraries(your-target PRIVATE RLyeh::Pnakotic)
```

Set `CMAKE_PREFIX_PATH` to the installation prefix, or set `RLyehPnakotic_DIR` directly to its package-metadata
directory, when Pnakotic is installed outside a standard system prefix. The
`RLyehPnakotic` install component contains only the header library, its CMake package metadata, and its license; tests
and future application targets are separate.
